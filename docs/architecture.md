# Architecture & Current Build State

A snapshot of how the portfolio is actually built right now, detailed enough that a new conversation can pick up work with just this file — `AGENTS.md` (facts, tokens, scope) — and the code itself, no prior chat history required. This is a reference, not a rulebook — updated at natural checkpoints (a finished feature, a settled design direction), not synchronously with every in-session experiment.

## Tech Stack
- Next.js 16 (App Router, Turbopack) + TypeScript
- Two real routes: `/` (the single-page site) and `/work/[slug]` (one static case-study page per client project — see Case Study Pages below, and AGENTS.md's "Case Study Pages" note on why this is the one deliberate multi-page exception)
- Tailwind CSS v4 (`@theme inline` token mapping in `globals.css`)
- Framer Motion — scroll reveals, hero load sequence, mobile menu transitions, the Projects section's line-draw flow diagram, command palette/case-study-modal-style overlays
- Lenis (`lenis/react`) — smooth/eased scrolling site-wide (`SmoothScroll.tsx`, mounted root in `layout.tsx`), `anchors: true` so in-page hash links get an eased `scrollTo` instead of a native jump
- `three` / `@react-three/fiber` — the hero's ambient particle field (`HeroCanvas.tsx`) and the 3D brand-mark centerpiece (`HeroMark3D.tsx`), both lazy-mounted via their own `*Loader.tsx` (`next/dynamic`, `ssr: false`)
- Zod — contact form validation, shared schema on both client and server
- Resend (plain `fetch`, no SDK) — contact form delivery
- `next/font/google` — four typefaces loaded and bound to CSS variables in `layout.tsx`: JetBrains Mono + Inter for English (display/headings vs. body), Anek Bangla + Noto Sans Bengali for the same two roles in Bengali — see Internationalization below for why these are a deliberately *paired* swap, not one font covering both jobs
- `middleware.ts` — per-request CSP with a nonce (`script-src 'nonce-...' 'strict-dynamic'`, no blanket `unsafe-inline`) covering `layout.tsx`'s inline theme/language-init scripts and JSON-LD; also sets a first-visit `geo-language` cookie from Vercel's edge geolocation headers (Bangladesh/West Bengal → Bengali default) — see Internationalization
- No CMS, static-first, deployed to Vercel — the backend exceptions are the contact form's Server Action and the geolocation cookie in middleware
- All content lives under `src/lib/data/` (one file per domain — `hero.ts`, `clientWork.ts`, `projects.ts`, `sideProjects.ts`, `experience.ts`, `education.ts`, `skills.ts`, `approach.ts`, `services.ts`, `contact.ts`, `nav.ts`, `commandPalette.ts`), typed via `src/types/index.ts` — never hardcoded in a component
- `src/lib/github.ts` exists (fetches GitHub stats/contributions server-side) but is currently **unreferenced anywhere in the app** — a live-GitHub-stat tile was tried in both Hero and How I Build, then removed as thematically mismatched; the module was left in place rather than deleted in case it's wanted again, but nothing calls it today

## Design Direction
"Kinetic glass futurism": bold oversized display type, glassmorphic surfaces (translucent panels + backdrop-blur + soft glow borders), gradient/glow accents, a cursor-reactive ambient light plus a cursor-following particle trail, generous negative space. See `AGENTS.md` for the token table.

**Direction history** (so future changes don't re-propose something already tried and rejected):
1. **HUD/systems-console look** — flat bordered panels, monospace coordinate labels, hairline grid. Rejected: "doesn't look like a developer website," read as an internal dashboard.
2. **Interactive comment-tree algorithm diagram** as the Hero centerpiece — rejected outright, removed entirely. A *different*, smaller-scoped version of this idea survives as How I Build's per-tile SVG node/line graphics (see Bento Tiles below) — those were kept and extended with hover animations; a standalone algorithm-visualization *section* is still explicitly out of scope per AGENTS.md.
3. **Client Work promoted over flagship projects** — Client Work leads (`#work`), the independent projects section ("What I've Built") follows it (`#built`).
4. **Chamfer (cut-corner) shape retired entirely, in favor of rounded corners everywhere** — including the favicon (`icon.tsx`). Don't re-add clip-path chamfer without being asked again.
5. **Section corner numerals (`01`, `02`, ...) replaced with a "// TAG" code-comment watermark** (`Section.tsx`'s `tag` prop, e.g. `// WORK`, `// BUILT`) — read as more "engineered," less like a slide-deck page number.
6. **A custom-cursor replacement was explicitly rejected** (AGENTS.md, Explicitly Out of Scope) — `CursorGlow.tsx` (ambient light layer) and `CursorTrail.tsx` (canvas comet-trail, added later) both leave the native OS pointer untouched by design; this was checked deliberately when the trail was added, not assumed.
7. **How I Build's tiles got a "traveling light" hover animation, then it was explicitly reverted** back to the simpler per-node pulse-on-hover treatment (kept) — the richer multi-light version (bent-path travel per graphic) was tried, refined twice, then removed entirely at the user's request. Don't re-add traveling-light animations to these graphics without being asked again; the static-node hover pulse is the current, settled state.
8. **A same-page modal for Client Work case studies was built, then reverted** in favor of dedicated `/work/[slug]` pages once the user confirmed they were open to multi-page routing — see Case Study Pages below. Don't reintroduce the modal pattern for this.

## Internationalization (English / Bengali)
A full bilingual system, not a stub — every section, nav item, and most data content has both `en` and `bn` values.

- **Data shape**: `Localized = { en: string; bn: string }` (`src/types/index.ts`). Any user-facing copy that could reasonably be read in either language uses this; true proper nouns/identifiers (person's name in URLs, tech/brand names like "Next.js", CSS/notation strings) stay plain strings instead — see the type's own doc comment for the exact line each field draws.
- **Reading a field**: always `t(field, language)` (`src/lib/i18n.ts`) — never `.en`/`.bn` accessed directly, so a future fallback rule only needs to change in one place. `localizeNumber(value, language)` converts Arabic digits to Bengali digits (stat counters, durations, dates) the same way, everywhere a number renders.
- **UI-chrome copy** (button labels, section eyebrows/titles, terminal prompts — not per-entity content) lives in `src/lib/i18n-strings.ts` as one big `strings` object, consumed the same way as data fields (`t(strings.foo.bar, language)`).
- **`useLanguage()`** (`src/lib/useLanguage.ts`) — `useSyncExternalStore` over a `data-lang` attribute on `<html>`, watched via `MutationObserver` (same pattern as `useTheme()`). `LanguageToggle.tsx` flips it and writes `localStorage`.
- **Fonts**: Bengali gets its own *paired* stand-ins rather than one font covering both English roles — Anek Bangla (heading, `--font-bengali-heading`) chosen to match JetBrains Mono's structured/technical character; Noto Sans Bengali (body, `--font-bengali-body`) chosen to match Inter's neutral-grotesque character. Applied via plain (unlayered) CSS overriding the compiled `.font-mono`/`.font-sans` utility classes under `:root[data-lang="bn"]` — overriding the `--font-mono`/`--font-sans` *variables* doesn't work, since Tailwind's `@theme inline` bakes the resolved font reference into the compiled rule at build time.
- **A known, deliberate rendering compromise**: `.gradient-heading` (Hero's name, Contact's headline — the only two `bg-clip-text` gradient headings) breaks Bengali's reordered pre-base vowel-sign glyphs when `background-clip: text` is applied, confirmed by isolating the two variables in testing. No CSS fix exists, so Bengali mode falls back to a flat `color-mix(in srgb, var(--text-primary) 75%, var(--accent) 25%)` instead of the real two-color gradient on just these two headings — chosen over a flat `--accent` because it approximates the gradient's actual dominant tone (mostly text-primary, accent only at the very tail) rather than its most saturated stop.
- **Phonetic transliteration, not translation**: tech/brand names (`strings.techSounds` in `i18n-strings.ts`) spell the same Latin name in Bengali script by sound (e.g. "Next.js" → "নেক্সট.জেএস") — consumed by `TechChip.tsx` (so every tech-name pill site-wide reads in Bengali script when the site is) and `BrowserChrome` (ClientWork.tsx). Unlisted names fall back to their own spelling.
- **Location-based first-visit default**: `middleware.ts` reads Vercel's edge geolocation headers (via `@vercel/functions`'s `geolocation()`) and sets a `geo-language` cookie (Bengali for Bangladesh/West Bengal, English elsewhere) the first time a visitor has no explicit choice yet. `layout.tsx`'s pre-hydration init script reads `localStorage["language"]` first (an explicit `LanguageToggle` click) and only falls back to the cookie — a manual toggle always wins and is never silently overridden on a later visit. Resolves to English in local dev and on any host without that header.
- **Command Palette, `⌘K`** (`CommandPalette.tsx`) — a searchable jump-list over every section, reusing each section's own `strings.*.eyebrow` (DRY, no duplicated copy) rather than a separate label list. Matches against both the visible label and the item's `id`.

## Page Structure
`src/app/page.tsx` (single scroll route `/`) order: `Hero` → `ClientWork` → `Projects` → `SideProjects` → `Skills` → `Experience` → `HowIBuild` → `Services` → `Contact`, closed by `Footer`.

Each section (except Hero) is wrapped in `Section.tsx`, which centrally provides: the scroll-triggered fade+rise reveal, the "// TAG" corner watermark, the eyebrow pill + title (`SectionHeading`, opt-out via `renderHeader={false}` for sections that compose their own header layout — Skills does this), and optional `tint` (alternating `bg-surface/40` band).

1. **Hero** (`Hero.tsx`, id `top`) — name, dual role badges (blue/maroon per-word, not a pill), pulsing `--status-live` status line, CTA row (`View My Work` wrapped in `Magnetic.tsx`, `Get in Touch` text link), stats row (`heroStats` via `CountUp`). Background: two `aurora-blob` blurred gradients plus `HeroCanvas` particle field (three.js, lazy). Right column: `HeroMark3D` — the brand mark scaled into a wireframe icosahedron with a soft inner core, continuous rotation plus pointer-driven tilt, theme-aware hex colors (WebGL materials need literal hex, not CSS vars), falls back to a flat badge without WebGL, freezes under `prefers-reduced-motion`. Mobile: the "Scroll" indicator sits in normal document flow below the mark (`md:absolute` only from `md` up) rather than always-absolute — on short/tall mobile viewports an absolute `bottom-8` could land on top of the mark instead of the true viewport bottom.
2. **Client Work** (`ClientWork.tsx`, id `work`, tag `WORK`) — see Work Section below.
3. **Projects** (`Projects.tsx`, id `built`, tag `BUILT`) — see Projects Section below.
4. **Side Projects** (`SideProjects.tsx`, id `side-projects`, tag `BUILDS`) — lightweight fun-utility cards (password generator, packing list), deliberately *not* styled like Work/Projects cards (no screenshot, no chrome bar, no tech chips) so they don't imply the same depth as a real case study. Live-status dot only lights up once `href` is a real URL.
5. **Stack** (`Skills.tsx`, id `stack`, tag `STACK`, `renderHeader={false}`) — a terminal-panel visual (`$ rafi --stack` prompt, `--flag value, value, ...` rows, blinking trailing caret), not a chip grid or marquee. Rows (`StackRow`) stagger in on scroll via `whileInView`; the trailing `$` + caret line is *also* `whileInView`-animated, delayed to start only after the last row's own animation finishes (computed from `skillGroups.length`) — a real terminal's next prompt doesn't appear until the previous output has finished printing, and this used to be a static always-visible element before that was fixed. The three top-left "traffic light" dots light up (blue → blend → maroon) on hovering the whole panel, same treatment as `ClientWork`'s `BrowserChrome`.
6. **Experience** (`Experience.tsx`, id `experience`, tag `EXP`) — see Experience & Education below.
7. **How I Build** (`HowIBuild.tsx`, id `approach`, tag `APPROACH`) — **not in the nav** (`navLinks` only has Work/Stack/Experience/Contact). See Bento Tiles below.
8. **Services** (`Services.tsx`, id `services`, tag `SERVICES`) — **not in the nav either.** Three "pinned to a moodboard" cards (rotated, staggered offset, thumbtack decoration), the one place the palette opens up past blue/maroon into wider Catppuccin hues (mauve/sapphire/teal) per AGENTS.md. Design/graphics/branding services, positioned as *additional* to development, not a replacement framing ("never call Rafi a freelancer" still applies here).
9. **Contact** (`Contact.tsx`, id `contact`) — gradient closing headline ending in three literal `.` characters that pop in sequentially on a loop (`typing-dot`/`typewriter-dot`, `steps(1,end)` — a hard cut, not an eased fade, "like a character being typed"; colored via the same `--accent` blue the heading's own gradient tail uses, not a flat unrelated tone), direct email (with a copy-to-clipboard button, checkmark feedback)/location/GitHub/LinkedIn links, plus `ContactForm.tsx` (see Contact Form below).

## Work Section (`ClientWork.tsx`)
Uniform 3-column grid (`sm:grid-cols-2 lg:grid-cols-3`), every cell the same shape/weight — no spotlight card.

- `WorkCard` links to that project's own case-study page (`/work/[slug]`, `next/link`) — **not** straight to the live site or an in-place modal (a modal version was built and explicitly reverted; see Direction History). `hover-glow-panel` class, `BrowserChrome` fake dots+label bar, fixed `16/10`-aspect screenshot, `min-h-36` text block (category, name + `ArrowUpRight` hover reveal, description, first 2 tech chips pinned to the bottom via `mt-auto`) — `min-h`, not a fixed `h-36`: a fixed height let a longer description overlap the tech pills below it on some cards, `min-h` lets the card grow instead. Mobile: below `md`, the real screenshot shows by default instead of the icon placeholder (no persistent `:hover` on touch to reveal it otherwise).
- Two curated non-project tiles in `buildGridItems()` (hand-placed, not algorithmic): `StatShowcase` at slot 5 — a huge `--gradient-signature`-clipped number sourced from `heroStats`'s "Sites Shipped" entry; `WorkFillerTile` closing the grid — full gradient fill, bleeding `Send` icon, "Open to new projects" linking `#contact`.
- Data: `clientWork.ts`, 7 `ClientProject` placeholder entries (generic names, `href="#"`, verified-reachable stock Unsplash covers). Each has a stable `slug` feeding its case-study route.

## Case Study Pages (`/work/[slug]`)
The one deliberate multi-page exception (AGENTS.md, "Case Study Pages") — added so a project's depth doesn't have to clutter the card, and so each project gets a real, indexable, shareable URL instead of same-page modal content a crawler would never see as a separate page.

- **Route**: `src/app/work/[slug]/page.tsx` — a Server Component. `generateStaticParams()` returns every known slug (the project list is static data, not user input). `generateMetadata()` sets a per-project `<title>`/description — the actual SEO payoff over a modal.
- **`icon` never crosses the Server → Client boundary**: `ClientProject.icon` is a component reference (a function), which Next.js can't serialize into the Client Component below it. The page rest-destructures it out (`const { icon, ...caseStudyProject } = project`) rather than listing every other field by hand, so a newly added `ClientProject` field passes through automatically instead of silently getting dropped.
- **`CaseStudy.tsx`** (Client Component, renders the actual page): back-to-work link, category + name + optional "Visit Site" link (only when `href` is a real `http` URL), cover image, description, then five **conditionally-rendered** sections — Challenge, Approach (styled as the same `//`-prefixed callout Projects' own highlight uses), What Shipped (bullet list), Outcome, Gallery (2-col image grid) — followed by the tech-stack chip list. Every one of those five is optional on `ClientProject` and *skipped entirely* when absent, never shown empty — today's 7 placeholder entries have none of them set, matching AGENTS.md's placeholder-honesty rule (no invented problem/role narrative for a project with no real specifics yet).
- **Cross-page navigation had to be fixed for this to work**: `Navbar.tsx`, `Footer.tsx`, and `CommandPalette.tsx` all link to homepage sections via bare `#id` hrefs so Lenis's `anchors: true` can intercept them for an eased same-page scroll — that only resolves on the homepage itself. Each component now checks `usePathname()` and prefixes `/` (e.g. `/#work`) when not on `/`, so clicking "Work" from a case-study page does a real navigation home followed by the browser's own hash jump, instead of silently doing nothing.
- **`sitemap.ts`** lists the root page plus one entry per `clientProjects[].slug`.
- **Content template**: `docs/Case_Study_Content_Template.md` — a fill-in-the-blanks worksheet mapping directly to `ClientProject`'s fields, for preparing real content before it goes into `clientWork.ts`.

## Projects Section (`Projects.tsx`)
Desktop (`md` and up): full-width editorial tabs, one project selected at a time (`AnimatePresence mode="wait"`), not a stacked list — content pane height stays constant regardless of project count. Tab strip: `flex-wrap`, active tab underlined via a shared-`layoutId` gradient bar.

Mobile (below `md`): the tab strip is replaced entirely by a **stacked accordion** (`ProjectAccordionItem`, one open at a time, tap to expand/collapse) rather than a squeezed copy of the desktop tabs — a horizontal-scrolling tab row plus every project's full deep-dive stacked under it would mean scrolling sideways *and* down just to read one project.

Per-project panel content (shared shape, desktop panel and mobile accordion body): a large `--gradient-signature`-clipped typographic stat (e.g. `O(N)`, `3`) + label, `FieldLabel`-headed blocks for "The Approach" (a bordered `//`-prefixed callout — the same visual language `CaseStudy.tsx` reuses for its own Approach section), "Mechanism" (`FlowSteps`, below), "Stack" (tech chips), plus `LinkBadge`s (Live Demo / GitHub / "Private Repo") only rendered per project when that field is set. The `md:items-center` on the stat/content grid vertically centers the stat block against the taller content column instead of pinning it to the top.

- **`FlowSteps.tsx`** — renders `project.flow` (a short project-specific mechanism, e.g. `["Flat list", "Hash-map", "Tree"]`) as dot-and-label nodes connected by lines; each connecting line animates `scaleX: 0 → 1` via `whileInView`, staggered per step.
- Data: `projects.ts`, 2 `Project` entries — Reddit Clone (live demo linked) and Blog Manager & CMS Dashboard (`private: true`, per AGENTS.md — a private Semigon repo).

## Experience & Education (`Experience.tsx`)
Single section, two visually distinct halves.

## Bento Tiles (`HowIBuild.tsx`)
Six tiles: five `PointCard`s (data: `approachPoints` in `approach.ts`) plus one `CtaTile`. Every `PointCard` is a fixed `h-80`; the grid's closing row (`CtaTile` + the last `PointCard`, "Production-Grade from Day One") is a shorter `h-64` instead — deliberately smaller than the other four (a closing beat, not another full-weight tile) but not shrunk to a cramped smaller-font variant either, via a `compact` prop on `TileShell`/`PointCard` that only changes height and graphic size, never font size.

- Each `PointCard` pairs its heading/description with a unique small SVG node/line diagram (`LayersGraphic`, `SchemaGraphic`, `ConvergeGraphic`, `DualRoleGraphic`, `PipelineGraphic`) — a different topology per concept, not one shape reused. On hovering a tile (`group-hover`), that graphic's previously-static nodes pulse in a sequence that traces the shape's own meaning: Layers ripples top row to bottom row; Schema lights up outward from its hub in two rings; Converge sweeps down its chain into the root, then fans back out to the leaves; Dual-Role pulses both sides from their tips inward, meeting at center. (A richer "traveling light" version of this was built and then explicitly reverted — see Direction History #7; the current state is the static-node pulse only.) The icon badge itself also gets a subtle `scale`/`rotate` on hover, shared across all six tiles.
- `CtaTile` — the section's one full-`--gradient-signature`-fill tile (same recipe as `WorkFillerTile`), anchored bottom-left on desktop; `order-last` only below `sm` so it becomes the actual last tile on mobile instead of sitting second-to-last ahead of Production-Grade.
- No live GitHub stat tile — one was tried here (and in Hero) via `src/lib/github.ts`, then removed as thematically mismatched ("public repos/contributions don't fit this section"). The module is still in the codebase, unreferenced.

## Cursor Effects
Two independent layers, both explicitly *not* a custom-cursor replacement (AGENTS.md, Explicitly Out of Scope) — the native OS pointer is untouched by both.
- **`CursorGlow.tsx`** — a fixed full-viewport radial-gradient wash following the pointer, position set via direct `ref.current.style.setProperty` on mousemove (not React state, to avoid a re-render per pixel of movement).
- **`CursorTrail.tsx`** — a canvas-drawn comet trail: a chain of ~18 points, the head easing tightly toward the real cursor position and each subsequent point easing toward the one ahead of it a little more loosely, which bows the chain into a smooth curved tail rather than a rigid offset line. Rendered each frame as a blurred glow pass (one thick low-alpha stroke) plus a tapered core pass (per-segment width/color, `--accent` at the head fading to `--accent-secondary` at the tail — the same signature-gradient pairing used everywhere else). Its own `requestAnimationFrame` loop, not React state.
- Both: desktop only (`pointer: coarse` check), disabled under `prefers-reduced-motion`.

## Navigation
`Navbar.tsx`, sticky glass pill. Desktop: inline anchor links (`navLinks` in `nav.ts` — Work/Stack/Experience/Contact only) + scroll-spy active-state highlighting (`IntersectionObserver`, trigger band 15%–25% down the viewport) with a shared-`layoutId` pill sliding between the active link. Chrome is scroll-reactive (padding/background opacity ramp via `useScroll`/`useTransform`, not a binary toggle). Mobile: hamburger → dropdown, positioned via a dedicated plain-CSS `.nav-mobile-menu` class (`position: absolute`) rather than a Tailwind `absolute` utility — `.nav-glass`'s own plain-CSS `position: relative` silently wins over a same-specificity layered Tailwind utility regardless of class order (a general gotcha in this codebase: hand-written CSS in `globals.css` is unlayered and beats `@layer utilities` rules); without the dedicated class the dropdown used to sit in normal document flow and push the whole page down when it opened. All nav/brand-mark/command-palette links are pathname-aware for cross-page navigation from `/work/[slug]` — see Case Study Pages above.

## Theming
Dark (Mocha) / light (Latte), same semantic token roles, real toggle. Default follows system `prefers-color-scheme`; explicit choice persists to `localStorage` and sets `data-theme` on `<html>` via a pre-hydration inline script in `layout.tsx` (no flash of the wrong theme). Same pre-hydration-script pattern covers `data-lang` (see Internationalization). Both scripts run under the CSP nonce from `middleware.ts` rather than a blanket `unsafe-inline`.

## Contact Form
`ContactForm.tsx` (client) + `src/lib/actions/contact.ts` (Server Action) + `src/lib/validation/contact.ts` (shared Zod schema, imported by both):
- Validated both ends (`noValidate` on the form, fully custom validation UI). Client: on-blur + on-submit. Server: the same schema is the actual gate.
- Delivery via Resend's REST API (`fetch`, no SDK). Missing `RESEND_API_KEY` → logs server-side, generic safe error to the visitor.
- Honeypot field (`company`, visually hidden + `tabIndex={-1}`) — filled means bot, silently returns fake success.
- All four UI states: idle, pending, success (replaces the form), error (inline per-field + form-level).
- No persistent rate-limiting — would need Redis/KV this static-first site doesn't have.
- Sender is Resend's shared test address (`onboarding@resend.dev`) until a `rafiera.com` address is verified in the Resend dashboard.

## Motion Rules
- Hero: one orchestrated staggered load sequence, fast, no bounce.
- Every `Section`-wrapped section: scroll-triggered reveal (fade + rise, `whileInView`, `once: true`), handled centrally by `Section.tsx`.
- Hover on cards/tiles: glow-border intensify (`.hover-glow-panel`, a `::after` opacity fade — never an animated box-shadow blur radius, which repaints every frame under `backdrop-filter`) — ClientWork/SideProjects cards additionally get a `translate`/`box-shadow` lift on hover now (a later, deliberate exception to the earlier "no lift, tried and rejected" rule; kept because it read as too flat once other cards elsewhere on the site started lifting on hover).
- **Tailwind v4 gotcha confirmed repeatedly this build**: `hover:-translate-y-*`/`scale-*`/`rotate-*` utilities compute through the native CSS `translate`/`scale`/`rotate` properties, not the legacy `transform` property — `getComputedStyle(el).transform` reads `"none"` even when the utility is correctly applied; check `.translate`/`.scale`/`.rotate` instead when verifying via computed style.
- Projects/CaseStudy's `FlowSteps`-style connecting lines: `scaleX` + `transformOrigin: left`, staggered per index.
- Experience timeline's / Hero's stat-dividers' `trail-light`: CSS keyframe, `top`/`opacity` (or `left`/`opacity` for the horizontal `flow-light` variant) only, percentage-based.
- How I Build's per-graphic node pulse: `transform: scale()` + `opacity`, `transform-box: fill-box` so the pivot is each SVG shape's own center, delay set inline per node (depends on that node's position within its own graphic's shape).
- Contact's trailing `.` dots: `steps(1, end)`, not eased — a hard cut, "like a character being typed."
- Cursor-reactive ambient glow/trail: see Cursor Effects above.
- `prefers-reduced-motion` respected globally via `<MotionConfig reducedMotion="user">` in the root layout, plus manual `@media (prefers-reduced-motion: reduce)` guards for every CSS-keyframe animation Framer Motion's config doesn't cover.

## Engineering Requirements
- All editable content lives under `src/lib/data/`, typed via `src/types/index.ts` — never hardcoded in a component.
- Responsive down to mobile; grids/timeline reflow for any N; Projects' desktop tabs vs. mobile accordion is a deliberate structural fork, not just a CSS reflow.
- Visible keyboard focus states throughout.
- CSP with a per-request nonce (`middleware.ts`); `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, HSTS, `Permissions-Policy` set in `next.config.ts`; `poweredByHeader: false`.
- SEO: per-page metadata (root + each case study), JSON-LD (Person + WebSite), `sitemap.ts` (root + every case-study slug), `robots.ts`, file-based `opengraph-image.tsx`/`icon.tsx` — see the SEO/security audit commit history for the full pass.

## Verification Workflow
`next.config.ts` sets `distDir: process.env.BUILD_VERIFY_DIR || ".next"` — running `BUILD_VERIFY_DIR=.next-verify npm run build` produces a fully isolated production build that never touches or crashes the live `next dev` server's own `.next`. Always clean up afterward (`rm -rf .next-verify`; the build also rewrites `tsconfig.json`'s `include` list as a side effect — `git checkout -- tsconfig.json` after).

**A real, repeatedly-confirmed dev-server staleness bug this build surfaced**: after editing `globals.css` (and occasionally after adding new route files), the running Turbopack dev server can keep serving the *previous* compiled CSS/bundle indefinitely — confirmed by fetching the actual served bundle (`curl` the `<link rel=stylesheet>` URL from the page HTML and grep it directly) rather than trusting the browser. A plain restart isn't reliably enough; the fix that has worked every time is the full sequence: kill every `next dev`/`next-server`/`turbopack-node` process, confirm `.next` is actually gone (`rm -rf .next`, then verify with `test -d`), *then* start fresh and wait for it to be fully ready before checking again. A too-fast restart (old process not fully dead before `.next` is deleted) reproduces the same staleness.

For visual/behavioral verification, Playwright (installed ad hoc via `npm install --no-save playwright`, then `npm uninstall --no-save playwright` after — not a project dependency) takes screenshots, but for anything positional, timed, or animated, prefer `page.evaluate(() => el.getBoundingClientRect())` / `getComputedStyle()` / sampling a value across several `waitForTimeout` frames over trusting a single screenshot — several bugs in this build (the mobile menu layout shift, the cursor-trail path bend, the Skills terminal caret timing) were only actually confirmed fixed via computed-geometry/opacity/position checks, not by eye.
